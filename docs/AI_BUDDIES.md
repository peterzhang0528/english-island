# 伙伴小岛：Mia 和 Leo

伙伴小岛是独立于十关主线的自由走动模式，入口在页头「伙伴小岛」和关卡菜单底部，地址是 `/game/buddies.html`。岛上有两位只会说英语的小伙伴：Mia（9 岁，西雅图长大）和 Leo（9 岁，奥斯汀长大）。他们先自己玩，发现玩家后招呼玩家加入，然后带着玩家玩跟我走、摘苹果、捉迷藏和赛跑。

十关主线、K 的愿望地图和 200 段 JJ 录音都没有改动。

## 像转学到美国一样：先听，再说

Mia 和 Leo 不懂中文，也不翻译、不讲语法。玩家说中文时他们只会用英语表示没听懂。页面上的任务提示和可说的短语也全是英语；只有开始和结束面板用中文向家长和玩家说明。

| 阶段 | 玩家做什么 | 伙伴怎么配合 |
| --- | --- | --- |
| 1 Listen | 只听，用走动参与 | 不要求开口，互相聊天并招呼玩家跟上 |
| 2 Say words | 说一个词 | 给二选一的机会（"Boat or tree?"），不说也继续玩 |
| 3 Say sentences | 说短句 | 问真实的问题，让玩家决定去哪儿并带队 |

完成第一轮游戏或第一次说出英语后进入阶段 2；阶段 2 中说对 4 次后进入阶段 3。开始面板可以直接选择阶段，选择保存在浏览器本地（`island-buddy-stage`）。

## 实时语音如何连接

两位伙伴各是一个 OpenAI GPT-Live 语音会话（一个会话只有一种音色）：Mia 用 `gleam`，Leo 用 `meridian`。

1. 浏览器为每位伙伴建立一个 WebRTC 连接，把 SDP offer 发给本站的 `POST /api/buddies`。
2. 服务器加上自己保存的人设、音色和密钥，调用 `https://api.openai.com/v1/live/sessions`，把 SDP answer 交还浏览器。密钥不进入浏览器。
3. 音频直接在浏览器和 OpenAI 之间传输；字幕来自 `oai-events` 数据通道的转写事件。

两个会话之间不共享音频。玩家的麦克风一次只接给一位伙伴（刚说过话的那位），其余信息用简短的文字备注传递：

- `[Game] ...`：游戏里发生的事实，例如玩家到了小船旁边。
- `[Mia said] "..."` / `[Leo said] "..."`：另一位伙伴刚说完的话。
- `[New kid said] "..."`：玩家说的话（转写）或点选的短语。

轮流说话由页面保证，不只靠提示词。模型有时会主动回应一条本该只是“记住”的备注，所以伙伴只有在“轮到他”时才出声：游戏刚点名请他说一句，或玩家正在对他说话（麦克风有声音）。其余时候他的声音保持静音、不出字幕、也不转告另一位伙伴。玩家一句话没说完时，麦克风不会换到另一位伙伴。点选短语时，只有刚说过话的那位伙伴回答。

语音识别偶尔把中文写成拼音（例如 `Ni hao. Wo bu hui shuo ying yu`）。游戏会把汉字、带声调的拼音和这类常见拼音都算作“不是英语”，不计入玩家说过的英语句数。

游戏规则（`buddies-game.js`）决定玩什么、谁该开口、说话的要点；伙伴用自己的话说出来。捉迷藏时找人的伙伴不会被告知藏身处。GPT-Live 不接收画面，所以伙伴只知道这些文字备注里的世界状态。

服务器配置：

| 名称 | 用途 |
| --- | --- |
| `OPENAI_API_KEY` | 与愿望地图共用的服务器密钥，需要有 GPT-Live 权限 |
| `BUDDY_CLASS_CODE` | 班内共享的随机口令，16–64 位英文字母、数字、下划线或连字符；单独发给班内，不放在网址或源码里 |
| `OPENAI_LIVE_MODEL` | 可选，默认 `gpt-live-1` |

`/api/buddies` 只接受同源的 JSON 请求，内容限定为伙伴、阶段和一份 WebRTC 音频 offer；人设、音色和模型不能由浏览器指定。接口有请求大小上限、超时和尽力而为的频率限制（每个来源每分钟 8 个会话，即 4 次开局），错误信息不包含上游返回内容。

## 费用与时长

GPT-Live 按会话时长计费，安静时也计费。`gpt-live-1` 约 $0.05/分钟/会话，两位伙伴同时在线约 $0.10/分钟。为避免忘记挂断：

- 单次游玩上限 12 分钟，到时伙伴道别并结束。
- 页面切到后台超过 45 秒自动挂断；离开页面时请求关闭会话。
- 「End」按钮会先请求关闭两个会话，再释放麦克风。

频率限制只在单个服务器进程内生效，不能当作费用上限；公开部署前请在 OpenAI 项目里设置预算。

## 演示模式

服务器没有配置密钥、浏览器不支持 WebRTC，或玩家不想用麦克风时，可以选择「先试玩演示」。演示使用同一套游戏规则和固定台词，由浏览器自带的英语朗读声音读出，并始终显示 `DEMO · scripted lines, not AI`。演示里用点选短语代替说话，不是 AI 对话，也不代表实时语音的效果。

## 隐私

实时模式会把麦克风音频发送给 OpenAI，请求设置 `store: false`（这不等于替模型提供商作零保留承诺）。字幕和转写只显示在当前页面，不写入本站数据库。人设要求伙伴不询问姓名、学校、住址等个人信息。未成年人使用前请由家长或老师确认。

## 验证范围

自动检查覆盖接口校验与错误处理、人设与音色、游戏规则全流程、浏览器端事件处理（使用模拟的 WebRTC）和场景构建。演示模式已在 Chrome 中试玩。

实时语音已用真实密钥在本地 Chrome 中联调：两个会话都能建立并生成字幕，伙伴按游戏点名轮流说话，End 能结束会话。麦克风这一段用的是 Chrome 的模拟麦克风播放预先合成的语音（两句英语、一句中文）：英语被正确转写并得到一位伙伴的回答，中文得到的是“Huh? I don't get it.”。

以下内容还没有人实际验收：真人（尤其是孩子）对着真实麦克风说话的识别效果、两种音色实际听起来的差别和音量、外放时的回声、手机浏览器，以及部署到 Cloudflare 之后的线上环境。

## 正式站的班内试玩

首页进入「伙伴小岛」，或访问同一站点的 `/game/buddies.html`。固定网址不包含口令，也不依赖临时隧道。只在 Sites 的服务器秘密配置中设置模型密钥和随机班内口令。页面输入的口令只保存在本页内存中；服务端逐次检查，不把口令传给模型。两项配置缺少任意一项时只开放 Demo。清空或轮换口令会阻止后续开局，不会终止已经打开的会话。

临时代理的 120 个会话计数**不在 Sites 中生效**；当前没有跨实例的每日总次数硬上限。正式站首次部署可不设置班内口令，确认费用安排后再设置；只给本班发放口令，课后关闭。预算提醒也不是硬上限。

每次更新记录本次和上一版的 Git SHA 与 Sites 部署版本。按原站的发布流程合并并检查准确的主线提交，在同一 Sites 项目中保存版本并部署，不新建网站。公网验收：首页入口、无口令可 Demo／不可 Live、有口令两位伙伴均可建立语音会话、原十关及愿望地图入口仍在。若需回退，确认后在原项目重新部署先前验证的版本；不要强推改写 Git 历史。Git 本身不会更改线上网站或恢复秘密设置。
