# JJ 配音维护

JJ 的听感以第一关现有旁白为基准。新关卡应延续这一声线、语速和亲切感，让孩子换关时仍像在听同一个冒险伙伴说话。

## v0.3.0 的配音方案

- 保留第一关原有 **32 段音频**，不替换或重新编码它们。
- 第二关 **27 段音频**使用第一关参考配音重新生成，文件名采用 `l2-jj-*.mp3`；成品做了轻微的 `atempo=0.92` 速度调整。
- 第三关新增 **23 段音频**（16 句旁白、7 个单词），文件名采用 `l3-jj-*.mp3`；沿用第二关的第一关声音参考及 `Qwen/Qwen3-TTS-12Hz-0.6B-Base` 生成方案，成品采用相同的 `atempo=0.92`、限幅和单声道 24 kHz／48 kbps MP3 设置。
- 第三关加入后，原有 **59 个音频文件及清单条目均保持不变**；新增内容使 `voice.json` 总计 **82 条**。已有词句直接复用，不重复生成。
- 原始配音的 voice ID 与完整生成配置不可得，因此这是**基于参考声音的近似匹配**，不承诺音色完全一致，也不声称使用了原始声音模型。

可以先听 [第一关欢迎语](../public/game/audio/s-hi.mp3) 和 [树的任务提示](../public/game/audio/s-look-tree.mp3) 建立对照。参考音频是现有项目素材，来源与许可范围见 [第三方说明](../THIRD_PARTY_NOTICES.md)；不要从学生或其他人的私人录音中自行补充声音参考。

## 新增一句英语的流程

1. **确定文本。** 列出实际播放的单词、提示句、计数和通关对白。检查拼写、标点、缩写，配好中文字幕。先查看 `public/game/audio/voice.json`，已有相同词句就复用现有文件。
2. **准备一致的参考。** 保留第一关原文件作为基准；如生成工具需要转换采样率或拼接短参考，只在临时工作副本上处理。提供与参考音频逐字对应的英文转写，不把目标句子当作参考转写。
3. **生成并听取对照。** 沿用维护者确认的参考声音方案。先生成一两句，与第一关交替试听，确认后再批量生成；不要为新关卡随意换一个默认系统声音。
4. **整理成品。** 使用稳定文件名，例如 `l3-jj-s-plant-seed.mp3`。适度调整音量或语速后检查清晰度、句首句尾与自然停顿；`0.92` 是第二、三关采用的速度参数，不是所有新声音都必须照抄的数值。
5. **更新清单。** 成品放入 `public/game/audio/`，并将准确英文、相对文件名和最终文件的实测时长写入 `voice.json`。
6. **验证后提交。** 运行自动检查，再通过实际关卡试听；在 PR 中提供参考文件名、新增文本、生成工具／模型的公开名称、关键处理参数和对比结果。

示例清单格式：

```json
{
  "plant a seed in the soil.": {
    "f": "l3-jj-s-plant-seed.mp3",
    "d": 1.553
  }
}
```

这是格式示例，时长应替换为实际测量值。键必须等于游戏传入文本经过 `trim().toLowerCase()` 后的结果；`f` 是相对 `audio/` 的文件名，`d` 的单位是秒，应按最终处理后的文件测量。清单中的英文键就是播放文本的记录；生成用的参考转写也应在 PR 或可公开的来源记录中说明。

## 播放与验收

关卡只通过共享的 `public/game/js/voice.js` 播放旁白，统一使用队列、取消、静音和暂停；不要另起一个 `speechSynthesis` 播放器。

清单中已有的录音加载失败时，共享模块会按该段时长静默等待，保留字幕节奏，避免突然更换说话人。未在清单中找到的临时文本仍可能回退到浏览器语音；系统声音因设备而异，不能当作正式关卡配音。自动测试会检查关卡文案是否全部登记。发现某一句无声或换声线时，先检查清单请求、文本键和 `f` 对应文件是否成功加载。

合并前至少核对：

- 第一关原有 32 个文件保持不变；第三关接入也已核对第二关 27 个文件及全部原有清单条目未变。需要调整已有音频时单独说明影响。
- 新增句子的文本、文件和时长一致，没有缺词、截断、明显底噪或音量突变。
- 第一关提示与新关提示交替播放时，声线与语速接近；单词点读和完成对白也保持一致。
- 静音、重听、取消上一句、帮助暂停与恢复都能正常工作。
- `npm test` 通过；试听中仍能听出的差异如实写入 PR，自动测试不会判断声线是否相同。

仅提交可公开的成品和必要记录。不要提交 API 密钥、服务账号、临时鉴权下载地址、个人路径或私人原始录音。
