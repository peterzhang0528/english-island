# 为小岛添加下一关

先让一个短故事完整地跑通，再增加场景细节。第三关的 `day3.html`、`world3.js`、`bootstrap3.js` 和 `day3.css` 可以作为结构参考；不要复制整套共享音频、贴图和 Three.js。

## 1. 从学习任务开始

在新关卡 Issue 中写出四件事：

| 内容 | 例子：花园关卡 |
| --- | --- |
| 故事与目标 | 帮新朋友种出一朵花 |
| 核心词 | SEED、SOIL、WATER、FLOWER |
| 行动顺序 | 打招呼 → 找种子 → 松土 → 播种 → 浇水 → 分享花朵 |
| 完成证据 | 花朵长出、朋友回应、词袋和通关卡展示本次发现 |

英文尽量短，让动作解释词义；中文帮助理解。一次只突出一个可操作目标。旁白、单词点读和完成后的重听都属于关卡的一部分。

## 2. 新建独立关卡文件

以第四关为例，新增：

```text
public/game/day4.html
public/game/day4.css
public/game/js/bootstrap4.js
public/game/js/world4.js
```

- HTML 保留加载状态、WebGL 失败提示、标题、提示语、动作按钮、词袋、帮助与完成卡。使用相对路径，保证独立入口也能运行。
- `bootstrap4.js` 动态导入场景；成功后启用开始按钮，失败后展示可恢复的错误状态并通知父页面。
- `world4.js` 管理本关状态、场景、交互和消息。引用现有 `vendor/three.module.min.js`、`textures.js`、`sfx.js`、`voice.js`。
- 在 `game.css` 上叠加本关样式，不要为了一个关卡改坏已有页面。

先用 [README 中的静态服务器](../README.md#只研究游戏场景) 打开 `/game/day4.html`，再接入完整网站。直接通过 `file://` 打开不属于支持的运行方式。

## 3. 保持明确的状态与动作

目前三关使用同一组阶段编号：

| `step` | 含义 |
| --- | --- |
| `0` | 开始画面／开场剧情 |
| `1` 至 `5` | 当前任务阶段；一个阶段可以包含有限次收集 |
| `6` | 已完成 |

第三关用 `prepared`、`planted`、`watered`、`grown`、`shared` 记录松土、播种、浇水、成长与分享，每个阶段的一次动作照顾整座花床。

例如第二关的 `step: 3` 包含三束麦子。每束有独立的 `harvested` 状态，重复点击不会再次计数。进入异步动作前同步设置 `busy = true`，动作和讲解完成后再释放；帮助打开、暂停、通关弹窗显示时也要阻止任务动作。

新关卡优先沿用六个进度节点。若需要不同阶段数，必须一起修改外层进度显示、完成判断和测试，不能只改变场景里的数字。

状态只保存业务事实，例如材料数量、阶段、暂停原因。由这些事实推导当前目标与按钮文案，避免同时维护多套互相矛盾的进度。

## 4. 接入网站菜单

当前代码显式支持 `1 | 2 | 3`，**新增一个 HTML 文件不会自动出现在菜单中**。添加第四关时请检查：

| 文件 | 需要同步的地方 |
| --- | --- |
| `app/page.tsx` | `Level` 类型、`chapters` 文案与步骤、菜单中的关卡列表、URL 参数读取、已完成关卡过滤、完成标题 |
| `components/IslandGame.tsx` | 关卡类型、iframe 的 `src`／`title`、导航消息中允许的关卡编号 |
| 本关 `bootstrap` / `world` | 状态消息的 `level`、导航按钮、独立页面跳转 |
| 相关自动测试 | 页面与资源自动发现、协议、可点击目标、任务状态、音频覆盖 |
| `README.md` / `CHANGELOG.md` | 新关卡入口、玩法与更新内容 |

网页用 `?level=2` 或 `?level=3` 直接选择第二关或第三关；`localStorage` 保存最近关卡和完成徽章。切换关卡会重新加载对应 iframe，不恢复未完成的材料进度。新增关卡时保持这个行为明确，或者在 PR 中说明存档变化。

## 5. 父页面与 iframe 消息协议

网站外层不直接修改 Three.js 场景。浏览器消息在双方校验同源及发送窗口后才处理。`targetOrigin` 使用 `location.origin`，不要改成 `"*"`。

### 游戏 → 网站：进度

```js
parent.postMessage({
  type: 'island-status',
  level: 4,
  ready: true,
  step: 1,
  busy: false,
  words: ['SEED'],
  muted: false,
  completed: false,
}, location.origin);
```

`words` 是已发现的英文大写词数组，`completed` 只在真实完成时为 `true`。关卡可以附加自己的计数，如第二关的 `egg`、`milk`、`wheat`、`cake` 和 `paused`。加载失败可以发送 `ready: false` 和面向用户的 `error` 文本；不要把环境路径或原始堆栈作为用户提示。

第一关的旧状态消息未包含 `level`，当前桥接组件会补上所加载关卡的编号。新关卡应始终显式发送 `level`。只在状态变化时通知父页面，避免每帧传输场景数据。

### 网站 → 游戏：动作

```js
// 网站中触发；IslandGame 会转发给当前 iframe。
window.dispatchEvent(new CustomEvent('island-command', {
  detail: { command: 'speak', word: 'seed' },
}));

// iframe 收到的格式：
// { type: 'island-command', command: 'speak', word: 'seed' }
```

| `command` | 作用 |
| --- | --- |
| `start` | 开始本关，重复请求不应重入开场 |
| `act` | 执行当前任务动作，与空格和动作按钮使用同一入口 |
| `mute` | 切换静音，使用共享 `sfx.muted` 持久化 |
| `restart` | 重新开始本关 |
| `help` | 打开／关闭帮助；帮助期间暂停 |
| `summary` | 已完成时打开通关卡；未完成时不跳关 |
| `speak` | 重听 `word` 指定的词或句子 |
| `pause` / `resume` | 显式暂停／恢复；目前第二、三关支持，第一关没有这两个消息分支 |

`fullscreen` 由外层 `IslandGame` 处理，不会转发给场景。新关卡应支持表中的基本命令，并参照第三关支持独立的暂停与恢复。

iframe 的消息监听至少保留以下检查：

```js
if (event.origin !== location.origin ||
    event.source !== parent ||
    event.data?.type !== 'island-command') return;
```

父页面也必须确认消息来自当前 iframe。页面切换后旧关卡的消息不能覆盖新关卡状态。

### 游戏 → 网站：换关

```js
parent.postMessage({ type: 'island-navigate', level: 4 }, location.origin);
```

父页面先确认该关卡存在，再切换。独立运行时 `parent === window`，应直接跳转对应 HTML；不要只发一个无人处理的消息。

## 6. 场景与点击目标

沿用方块几何和已有贴图，让新场景有自己的地形与标志物。重复的草地、树叶、麦秆等优先使用 `InstancedMesh` 或合并几何；控制移动端像素比和阴影成本。

为真正可交互的对象登记 `kind`、`word` 和可选索引。射线检测需要递归命中子网格，再向上找到业务对象；同时检查所有祖先的 `visible`。已收走的材料、隐藏蛋糕和装饰物不能误触发任务。

每个任务都准备一个镜头与明显的金色目标圈。确认桌面与手机纵向画面下，目标没有被提示语、词袋或配方卡遮住。点击、按钮、空格最终调用同一个受状态保护的动作函数。

第二、三关的 `window.__yf` 暴露了状态、目标和部分函数用于调试；这是调试入口，不是对外兼容承诺。自动检查可以使用真实 Three.js 的对象与射线计算，但这不能证明实际浏览器已渲染正确。

## 7. 统一旁白与新增音频

完整流程见 [JJ 配音维护](AUDIO.md)。第一关原有 32 段保留，第二关使用基于第一关参考声音生成的 `l2-jj-*.mp3`；原始 voice ID 不可得，因此是近似匹配，不承诺音色完全一致。

三关共用 `voice.js`。新增关卡应继续使用同一个 JJ 旁白声线，包括核心词、引导句、重复听和通关对白。合成新声音前先对照现有第一关样音，并与维护者确认沿用的声音配置；不要给每一关随意选择新的默认声音。

本地配音索引位于 `public/game/audio/voice.json`：

```json
{
  "a seed!": { "f": "day4-s-a-seed.mp3", "d": 1.2 },
  "seed": { "f": "day4-w-seed.mp3", "d": 0.7 }
}
```

这个片段只是格式示例，合并时填写真实文件名与实测时长。键必须与游戏实际传入文本经过 `trim().toLowerCase()` 后完全一致，包括标点和缩写。每一个关键单词和句子都要检查，包括帮助重听、完成卡、探索提示与动态计数。

- 优先使用已有录音；新增文件用稳定、能辨认含义的文件名，不覆盖共享词条来改变别的关卡音色。
- 通过 `voice.say(text, { interrupt })` 播放，使用共享的停止、静音和暂停机制，避免同时出现两路旁白。
- 已登记的录音加载失败时按清单时长静默等待，保留字幕节奏；未登记的临时文本仍可能回退到浏览器语音。正式关卡文案必须先登记录音，**回退可用不代表配音一致性已经通过**。
- 语音来源、生成工具与采用的声音配置应有可追溯记录；不要提交 API 密钥、个人原始录音或服务账号信息。
- 合并前实际听三组内容：第一关提示 → 新关提示、两个关卡中的相同词、开场 → 完成对白。检查声线、音量、语速、截断与重叠。

图形动作与等待也要暂停。第二、三关按帮助、外部暂停和页面隐藏分别记录原因；关闭帮助不能顺便解除另一个仍然有效的暂停。

## 验证你的关卡

先运行统一检查：

```sh
npm run typecheck
npm test
npm run build
```

资源检查会自动发现 `index.html` 和 `dayN.html`，并检查对应的 `world.js`／`worldN.js`；配音检查自动扫描所有 `worldN.js` 中的词汇、字面量对白和有限选项。新增动态文案或动态 DOM 标识时，仍需补充相应覆盖。

为新行为补有意义的检查：缺失资源、错误清单键、跨关卡消息、重复进入、材料重复计数、隐藏目标误命中，以及暂停后动作仍推进等。不要把一个只调用空函数的模拟写成“浏览器已完整通关”。

然后在支持 WebGL 的浏览器做一次真实体验：

- 独立 HTML 与网站 iframe 都能进入；桌面与手机纵向没有内容溢出或目标遮挡。
- 从头到尾分别用点击与动作按钮／空格完成任务，快速连续点击不会跳步或重复获得材料。
- 关键语句都能听到；静音后不出声，取消旧旁白不会阻塞下一句，重听不会产生叠音。
- 动作或讲解进行中打开帮助、关闭帮助、切到后台再回来，进度与音频能正确暂停和继续。
- 通关条件正确；词袋与卡片只包含实际发现的内容；下载的 PNG 可以打开，字体与画面没有截断。
- 切换关卡、重玩和返回已有关卡后，按钮和进度仍正常；共享文件有改动时，三个关卡都要复查。

在 PR 中写清浏览器、视口、自动检查结果以及未完成的验证。没有浏览器条件时可以先提交 Draft PR，请同学协助试玩；不要把未验证写成已通过。
